#  var,let ,const 的区别？

| 特性  |        作用域         |         变量提升          | 重新声明 | 重新赋值 |
| :---: | :-------------------: | :-----------------------: | -------- | -------- |
|  var  | 函数作用域/全局作用域 | 有（提升后值为undefined） | 允许     | 允许     |
|  let  |      块级作用域       |      有(暂时性死区)       | 不允许   | 允许     |
| const |      块级作用域       |      有(暂时性死区)       | 不允许   | 不允许   |

**暂时性死区(TDZ)**:从作用域顶部到变量声明之间的区域，如果在这个区域内使用该变量，会报错，而不是`undefined`

> 总结
>
> 1. var 是 ES5 语法，函数作用域、允许重复声明、存在变量提升；let/const 是 ES6 语法，块级作用域、禁止重复声明、有暂时性死区。
> 2. const 并非 “常量”，仅限制变量不能重新赋值，引用类型（对象 / 数组）的内部值仍可修改
> 3. 开发中优先用 const，需要赋值时用 let，彻底抛弃 var 能大幅降低代码出错概率。

## 变量提升

### 一、变量提升的本质：代码执行的两个阶段

JavaScript 引擎执行代码并非 “从上到下逐行执行”，而是分为两个核心阶段：

1. **编译阶段（词法分析 / 预编译）**：引擎会扫描代码，将变量 / 函数的声明 “收集” 到当前作用域的顶部（提升），但**不会执行赋值 / 函数体**。
2. **执行阶段**：逐行执行代码，处理赋值、函数调用等逻辑。

变量提升的本质，就是**声明在编译阶段被提升，赋值在执行阶段才生效**。

### 二、不同声明方式的提升机制（核心差异）

#### 1. `var` 的提升机制（最 “简单” 的提升）

`var` 的提升分为两步：

- 第一步：声明提升（编译阶段）：将 `var 变量名` 提升到当前作用域顶部，变量默认值为 `undefined`；
- 第二步：赋值执行（执行阶段）：代码执行到赋值行时，才会给变量赋予具体值。

#### 2. `let/const` 的提升机制（带 “暂时性死区” 的提升）

ES6 引入 `let/const` 后，提升规则发生了变化：

- **声明仍会提升**：编译阶段，引擎依然会识别 `let/const` 声明并 “标记”，但不会给变量赋默认值（区别于 `var` 的 `undefined`）；
- **暂时性死区（TDZ）**：从作用域顶部到变量声明行之间的区域，称为 “暂时性死区”，这段区域内访问变量会直接报错，而非 `undefined`；
- **赋值生效**：只有执行到声明行（`let a = 10`/`const b = 20`），变量才会被初始化，之后才能正常访问。

#### 3. 函数声明的提升（额外补充，帮助理解）

函数声明的提升优先级高于变量提升，且会**完整提升函数体**（区别于变量仅提升声明）

函数表达式（`var foo = function() {}`）仅提升变量声明，不提升函数体
